## 1. Executive Summary & Filtering Philosophy

High data quality is paramount when pretraining a compact 500M-parameter model. Larger models (e.g. 70B+) can sometimes absorb noisy web tokens through sheer capacity; small models, by contrast, suffer immediate perplexity and reasoning degradation when exposed to boilerplate, repeated spam, corrupted encoding, or autogenerated noise.

Our filtering architecture follows a strict, sequential **10-Stage Pipeline**:
Each stage executes in order of computational cost (cheapest deterministic filters first, expensive statistical and embedding filters last) to maximize throughput and ensure zero validation leakage.

## 2. Sequential Filtering Architecture

```
Raw Input Documents (JSONL)
   │
   ▼ [Stage 1: Format & Encoding Normalization]
   │  - Validate UTF-8; drop null/empty records; replace Mojibake; normalize NFC
   │
   ▼ [Stage 2: Length & Document Granularity Filter]
   │  - Exclude documents with < 100 characters or > 100,000 characters
   │
   ▼ [Stage 3: Language Identification]
   │  - English classifier threshold >= 0.85 (except dedicated multilingual pool)
   │
   ▼ [Stage 4: Text Quality & Heuristic Metrics]
   │  - Alphanumeric ratio: >= 0.65 for prose, >= 0.50 for code/math
   │  - Mean word length: 3.0 to 10.0 characters
   │  - Symbol spam & excessive punctuation thresholds
   │
   ▼ [Stage 5: Repetition & Boilerplate Elimination]
   │  - Line repetition ratio < 0.20; duplicate 13-gram ratio < 0.15
   │  - Strip HTML tags, markdown breadcrumbs, cookie notices
   │
   ▼ [Stage 6: Domain-Specific Filtering (Code & Math)]
   │  - Code: max line length < 1000 chars; drop minified JS, SVGs, lockfiles
   │  - Math: LaTeX environment verification; symbol integrity
   │
   ▼ [Stage 7: PII & Secret Redaction]
   │  - Redact IPv4, emails, AWS/GitHub secrets, private keys via regex
   │
   ▼ [Stage 8: Exact Deduplication]
   │  - Canonical text SHA-256 hash collision filter
   │
   ▼ [Stage 9: Near-Deduplication (MinHash LSH)]
   │  - Jaccard similarity threshold >= 0.80 clustered and deduplicated
   │
   ▼ [Stage 10: Evaluation Suite Contamination Shield]
   │  - 13-gram overlap filter against MMLU, GSM8K, ARC, HumanEval, and Val splits
   │
Clean Pretraining Ready Pool
```

## 3. Detailed Stage Specifications

### Stage 1: Format & Encoding Normalization
- **UTF-8 Enforcement:** Drop records with unparseable byte sequences.
- **Mojibake Detection:** Detect corrupted sequences (e.g., `Ã©`, `â€™`, `ï¿½`). Records containing more than 3 replacement characters (`\uFFFD`) are discarded.
- **Unicode Normalization:** Apply standard Unicode Normalization Form C (`NFC`) to unify composite characters.

### Stage 2: Length & Granularity Bounds
- **Minimum Length:** Documents with $<100$ characters or $<25$ words are discarded (insufficient context for causal modeling).
- **Maximum Length:** Documents with $>100,000$ characters are chunked into independent semantic documents at paragraph boundaries to prevent memory spikes during dataloading.

### Stage 3: Language Identification
- Use `fasttext` or lightweight n-gram language identifier:
  - English Target Pool: Probability score $P(\text{en}) \ge 0.85$.
  - Multilingual Pool: Explicit language metadata validation matching target scripts (Latin, Cyrillic, Han, Kana, Arabic).

### Stage 4: Text Quality & Statistical Heuristics
- **Alphanumeric Ratio:**
  $$\text{Ratio} = \frac{\text{Count of } [a-zA-Z0-9]}{\text{Total Characters}}$$
  - Web & Prose: $\text{Ratio} \ge 0.65$.
  - Code & Mathematics: $\text{Ratio} \ge 0.50$ (allows punctuation, brackets, operators).
- **Mean Word Length:** Must fall within $[3.0, 10.0]$ characters. Documents outside this range typically consist of concatenated URLs, hex dumps, or single-character lists.
- **Bullet / Ellipsis Ratio:** Documents with $>15\%$ ellipsis (`...`) or $>25\%$ bullet lists are discarded.

### Stage 5: Repetition & Boilerplate Elimination
- **Line Repetition:** If duplicate non-empty lines account for $>20\%$ of total document lines, the document is rejected.
- **N-Gram Repetition:** Duplicate character 13-grams exceeding $15\%$ indicate looped machine text or scraper errors; discarded.
- **Boilerplate Stripping:** Remove Common Crawl artifacts using regex patterns:
  - Cookie consent: `"This website uses cookies to ensure..."`
  - Navigation headers: `"Home > Products > Category > ..."`
  - Footer copyright notices: `"Copyright © 2024 All rights reserved."`

### Stage 6: Code-Specific Sanitization
- **Minified Code Filter:** Any file with maximum line length $>1,000$ characters is rejected (detects minified JS, compiled bundles, base64 strings).
- **Non-Code Exclusion:** Exclude files matching `.min.js`, `.min.css`, `.map`, `package-lock.json`, `yarn.lock`, `.svg`, `.hex`, `.bin`.
- **Comment-to-Code Balance:** Files consisting of $100\%$ comments or $0\%$ code are discarded.

### Stage 7: PII & Credential Redaction
All matching sensitive entities are masked with standard redaction tokens:
- **Email:** `[EMAIL]`
- **IPv4 / IPv6:** `[IP_ADDRESS]`
- **AWS API Keys:** `AKIA[0-9A-Z]{16}` $\to$ `[AWS_KEY]`
- **Private RSA Keys:** `-----BEGIN RSA PRIVATE KEY-----` $\to$ Discard entire file immediately.

### Stage 10: Benchmark Contamination Shield
- Extract all 13-gram shingles from standardized evaluation datasets:
  - GSM8k (test set)
  - MMLU (all subjects test split)
  - ARC Challenge & Easy
  - HumanEval & MBPP
  - ModernGPT Validation Split (`val_documents.jsonl`)
- Any pretraining document sharing a 13-gram overlap with the evaluation benchmark is **permanently quarantined and removed**.
